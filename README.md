# 剧场客服来信分流验收

按到件时刻生效的分流规则验收来信，分规则版本核对各队列负载和人工分诊量。

栖桥剧场观众服务中心，四名客服为大小两个剧场处理票务、无障碍服务和失物招领来信。客服从共享邮箱导出去标识的来信，导入时保留到件时间；运营专员在分流规则页登记每次演出调整引发的规则变更。验收运行在开跑时冻结规则快照，按各封来信的到件时刻采用当时生效的规则计分，不同规则版本的成绩分开核对，再把逐件验收明细交给票务组、观众服务组和前厅组定排班。

- 演出调整会发布新的分流规则，不同规则版本的成绩混在一起无法定排班。
- 历史邮件和验收批混用时，当天才出现的新词会提前影响词表和权重。
- 短句或多诉求邮件容易错投，一线需要知道哪些来信应转人工分诊。

## 业务模块

| 模块 | 用途 |
|---|---|
| 值班总览 | 查阅业务口径、当班流程及最新运行。主管可以核对审计记录。 |
| 来信明细 | 下载「栖桥剧场来信分流_20261120.csv」并核对字段。分析员可导入 UTF-8 CSV，保留到件时间、数据指纹和原始行。 |
| 分流规则 | 登记规则版本：生效时刻、签发序号和分流参数。同刻变更按签发序号取唯一版本，发布中断时旧版保持可查。 |
| 分流验收 | 选择批次提交后台计算，开跑时冻结规则快照，可从运行列表追踪状态。 |
| 分流结果 | 按规则版本分开核对业务指标、证据表和解释，通过来源链接回查数据。 |
| 验收复核 | 查看待处理或已完成记录。复核主管可提交验收决定及依据。 |
| 分流交付 | 按批查找结果，核对复核状态并下载相应的 CSV。 |

## 演示流程

1. 在分流规则页查看演示版本：R-20261118-A（11 月 18 日起，阈值 0.12）与 R-20261120-B（11 月 20 日 12:00 演出调整起，阈值 0.30）。
2. 11 月 20 日 09:00，从共享邮箱整理「栖桥剧场来信分流_20261120.csv」，保留各件的到件时间、归口和固定批次。
3. 导入后核对 18 封来信，其中 11 封训练件、7 封留出件；缺规则或版本重叠的批次会被整批拒绝。
4. 提交分流验收，运行在开跑时冻结规则快照：上午到件按 R-20261118-A、中午后按 R-20261120-B 分别计分。
5. 在分流结果中按规则版本比较宏 F1 与多数类基线，并查看各版本的自动分流覆盖率。
6. 逐件检查 QQ-TEST-07 的新词来信和人工分诊原因，核对每封来信采用的规则与同批次总分。
7. 验收中途再发布新规则不影响已冻结的快照；补到的迟到记录另起验收仍沿用各自开跑时的快照，重跑不重复计分。
8. 主管在验收复核页记录放行或复测决定，在交付页导出逐件分流明细。

## 计算口径

- CSV 明确标记 train 或 test 并保留到件时间。训练件拟合词表、逆文档频率、各标签质心和多数类。留出件只参与预测与验收计分。
- 每封留出件按到件时刻采用当时生效的规则版本；同一生效时刻的变更按签发序号取唯一版本。缺规则或版本重叠的批次整批拒绝。
- 连续汉字取相邻双字词，单字保留。英文字母和数字按连续串取词并转小写。仅保留训练中出现的词，限制词量时按训练文档频率降序、同频按词序取前 K 个。
- 以词频乘以 1 + ln((1 + 训练件数)/(1 + 训练文档频率)) 并做 L2 归一化。各类取归一化训练向量的均值，与留出件向量计算余弦相似度。
- 无命中词、最高分并列或低于所采用规则的阈值时转人工。最高余弦分衡量接近程度。训练多数类并列时按队列名称排序取首项。
- 验收运行在开跑时冻结规则快照，中途发布的规则与补到的迟到记录不影响本次计分，重跑沿用同一快照不重复计分。
- 成绩按规则版本分开计算：两种策略共用训练标签与该版本留出标签的并集计算宏 F1，零分母计零。人工分诊计入真实队列的漏分，覆盖率按自动分流量除以该版本留出总量计算。

## 本地开发

| 组件 | 实现 |
|---|---|
| 前端 | Nginx 与原生 HTML、CSS、JavaScript。`frontend/src/pages` 放页面，`components/common` 放共用表格、图表及表单。 |
| API | Python 3.11、FastAPI、SQLAlchemy。`backend/src/domain` 放本项目字段、业务计算和演示数据，`routes` 放接口，`models` 放表模型。 |
| 后台 | 独立 Python worker，通过 Redis 唤醒，从数据库租约领取计算，CSV 写入共享卷。 |
| 数据 | PostgreSQL 16 存储批次、规则版本、运行与审计。`backend/scripts/seed_demo.py` 可安全重复执行。 |

改动前端后执行 `docker compose up -d --build frontend`。改动接口或算法后执行 `docker compose up -d --build backend worker`，再刷新浏览器。如需保留数据，停止时执行 `docker compose down`。使用 `docker compose down -v --remove-orphans` 会清除该项目的数据库、Redis 和报表卷。

`.env.example` 中的 `COMPOSE_PROJECT_NAME`、`FRONTEND_PORT`、`BACKEND_PORT`、`DB_PORT`、`APP_SUBNET` 控制项目隔离。`DB_PASSWORD`、`JWT_SECRET` 和 `SEED_DEMO` 为本机演示默认设置。后端 `constants/enums.py` 与前端 `src/constants/enums.js` 保持角色、运行状态和复核状态一致。项目许可证见 `LICENSE`。
